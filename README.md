# Голосовой ассистент для задач, напоминаний и встреч

Прототип. Создает задачи, напоминания и встречи по фразе голосом или текстом, показывает расписание и находит старые записи по смыслу.

Работает на Yandex Cloud, оплата в рублях российской картой:

- запросы разбирает YandexGPT через OpenAI-совместимый API AI Studio;
- поиск использует эмбеддинги Yandex: text-search-doc для записей, text-search-query для запросов;
- речь распознает и озвучивает SpeechKit, распознавание ограничено фразами до 30 секунд.

Вместо облака можно подключить распознавание и озвучку в браузере, локальную Ollama или OpenAI, подробности в разделе "Другие провайдеры".

Автор: Артем.

## Быстрый старт

Нужен Python 3.10 или новее.

macOS и Linux:

```bash
cd voice_assistant
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run.py
```

Windows, командная строка `cmd`:

```bat
cd /d C:\voice_assistant
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python run.py
```

Перед первым запуском создайте в папке проекта файл `.env`:

```
PROVIDER=yandex
YANDEX_API_KEY=AQVN...
YANDEX_FOLDER_ID=b1g...
```

Откройте http://127.0.0.1:8000. Сервер работает, пока открыт терминал, остановка: `Ctrl+C`. После правок в `.env` перезапустите сервер.

Команда ниже делает по одному маленькому запросу к модели, эмбеддингам, распознаванию и озвучке. Стоит доли рубля:

```bash
python -m assistant.cli check --full
```

## Как обрабатывается команда

Модель разбирает фразу и выбирает действие. Данные проверяет и записывает обычный код, напрямую в базу модель не пишет.

1. Текст уходит в `POST /api/chat`. Голос браузер записывает в WAV (16 кГц, моно, 16 бит) и отправляет в `POST /api/voice`, сервер распознает его и дальше работает с текстом. ffmpeg не нужен.
2. `Assistant.handle` в `nlu/agent.py` собирает запрос к модели: имя пользователя, сегодняшнюю дату, даты на 8 дней вперед, часовой пояс, правила, до 5 последних упомянутых записей, журнал вызовов и последние реплики. Журнал идет в системный промпт, а не в диалог: реплики журнала модель копировала в ответ вместо настоящего вызова. Реплик по умолчанию 10, настройка `HISTORY_MESSAGES`. Даты в запросе нужны, чтобы модель переводила "завтра" и "в пятницу" в `YYYY-MM-DD`.
3. Модель пишет ответ или вызывает инструмент. Код проверяет аргументы, выполняет действие и возвращает результат модели. Цикл повторяется до текстового ответа, максимум 6 раз.
4. Реплики и журнал вызовов сохраняются в базу, ответ уходит в интерфейс. Если данные изменились, страница обновляет расписание.

Обычная команда занимает два обращения к модели: первое выбирает инструмент, второе пишет ответ. Если обращение к модели упало, реплика в историю не попадает.

Инструменты модели:

| Инструмент | Действие |
|---|---|
| `create_item` | Создать задачу, напоминание или встречу |
| `update_item` | Изменить название, дату, время, длительность, тип, повтор |
| `delete_item` | Удалить запись, у повторяющейся всю серию |
| `complete_item` | Отметить выполненной или вернуть в работу |
| `list_schedule` | Показать расписание за период |
| `search_items` | Найти записи по смыслу, в том числе в истории |

## Как ассистент уточняет

`Scheduler` не задает вопросов пользователю. Он возвращает статус, а модель по правилам из промпта пишет реплику.

| Статус | Когда | Что делает модель |
|---|---|---|
| `ok` | Действие выполнено | Подтверждает |
| `need_clarification` | Не хватает данных | Задает один короткий вопрос, ничего не создает |
| `ambiguous` | Подходит несколько записей | Перечисляет варианты, повторяет вызов с `item_id` |
| `conflict` | Встреча пересекается с другой | Спрашивает, ставить ли все равно; при согласии повторяет вызов с `force=true` |
| `not_found` | Запись не найдена | Сообщает об этом |
| `error` | Неверные аргументы | Исправляет их и повторяет вызов |

Запись нельзя создать без названия и даты, встречу и напоминание еще и без времени. Задача без времени показывается как "весь день". Встреча по умолчанию длится 60 минут, настройка `MEETING_DEFAULT_MINUTES`.

## Как находится запись

Для правки, удаления и отметки выполнения `Scheduler.resolve` ищет запись в таком порядке:

1. По `item_id`, если он известен.
2. По дате и времени: `on_date` и `at_time`. Если на этот момент есть одна запись, выбирается она, название не важно. Так находится встреча без своего названия.
3. По описанию через поиск. Будущие и повторяющиеся записи идут первыми. Запись выбирается, если все слова запроса есть в названии только у нее или ее оценка единственная в пределах 0,08 от лучшей. Иначе статус `ambiguous` и до 5 вариантов.
4. По контексту. В таблице `dialog_state` лежат до 5 записей, с которыми работал пользователь: так фраза "перенеси ее на завтра" находит нужную встречу.

Варианты из `ambiguous` попадают в журнал вызовов вместе с id. Когда пользователь выбирает вариант, модель берет его `item_id` из журнала и не начинает поиск заново.

## Встречи и повторы

Конфликты проверяются при создании и переносе, только для встреч со временем. Задачи и напоминания не конфликтуют, выполненные встречи не учитываются. Интервалы пересекаются, если `a1 < b2 and b1 < a2`. У повторяющихся встреч код сравнивает даты на 90 дней вперед.

Серия занимает одну строку в базе: в ней лежит правило с частотой, интервалом, днями недели и датой окончания или числом повторов. Даты вычисляет `dateutil.rrule` при каждом чтении. Выполнение отмечается по дням в поле `done_dates`, поэтому закрыть можно один экземпляр. Удаление и перенос меняют всю серию.

## Поиск по смыслу

`services/search.py` складывает две оценки: `0,8 * смысл + 0,2 * слова`.

- Смысл: косинусное сходство эмбеддингов запроса и названия.
- Слова: доля слов запроса в названии. Сравниваются первые 5 букв, поэтому "Иван" совпадает с "Иваном".

Запись попадает в выдачу, если совпало хотя бы одно слово или смысловая оценка не ниже порога: 0,35 для Yandex, 0,3 для OpenAI, 0,45 для локальной модели. Если сервис эмбеддингов недоступен, поиск идет только по словам.

Векторы лежат в таблице `embedding_cache`, ключ строится из имени модели и текста. Одинаковое название считается один раз, а при смене модели векторы считаются заново. API Yandex принимает одну фразу за запрос, поэтому приложение отправляет до 8 запросов в секунду (`YANDEX_EMBED_RPS`) и повторяет запрос с паузой при ответе 429.

## Голос и напоминания

SpeechKit принимает фразу до 30 секунд и 1 МБ. Если серверное распознавание не сработало, интерфейс переключается на браузер. Если не сработала озвучка, ответ читает браузер.

Страница раз в 30 секунд запрашивает `/api/upcoming`. Напоминание или задача считаются наступившими, если их время прошло не больше 12 часов назад и они не выполнены. Страница показывает баннер, а для новых записей подает сигнал. Закрытая страница не напоминает.

## Импорт истории из CSV

Файл `data/voice_assistant_events_1000_77e927b5d2.csv` с колонками `id,date,time,text` загружается при запуске для пользователя "Основной". Тип записи определяется по началу фразы: "встреча", "созвон", "демо" дают встречу, "напомнить" дает напоминание, остальное становится задачей. Строка получает `external_id=csv:<id>`, поэтому повторный импорт не создает дублей.

Около 380 уникальных фраз считаются в фоне примерно минуту, прогресс виден в интерфейсе. Пока расчет идет, поиск работает по словам. Если расчет упал, приложение повторит его при следующем запросе статуса.

```bash
python -m assistant.cli import-csv                     # импорт и эмбеддинги для "Основной"
python -m assistant.cli import-csv --user "Мария"      # история для другого пользователя
python -m assistant.cli embed                          # досчитать эмбеддинги
python -m assistant.cli stats                          # пользователи и количество записей
```

## Что происходит при сбоях

Ошибки модели код обрабатывает так:

- проверяет типы, допустимые значения и обязательные поля по схеме инструмента;
- приводит "завтра", "31.10" и "15" к датам и времени;
- возвращает ошибку модели как обычный результат, и модель повторяет вызов;
- распознает вызов, написанный текстом (`<tool_call>...`);
- отбрасывает ответ, в котором модель написала вызов инструмента обычным текстом и ничего не выполнила, и просит повторить; после второго такого ответа пользователь видит сообщение о неудаче, а не ложное подтверждение;
- убирает служебные строки из ответа и из истории на странице;
- переходит в JSON-режим, если модель не поддерживает инструменты (принудительно: `LLM_TOOLS_MODE=json`);
- передает модели сжатые результаты, расписание до 60 записей.

Ошибки сервисов `describe_error` в `providers.py` переводит в понятное сообщение: неверный ключ, нет роли, нет средств на балансе, превышен лимит запросов. Сообщение появляется вверху страницы или в чате. Расписание и история работают без ключей.

Поле `llm_ok` в `/api/status` для Yandex показывает только, что ключ и каталог заполнены. Рабочие ли они, проверяет `python -m assistant.cli check --full`.

## Данные

База SQLite лежит в `data/assistant.db`. Записи разделены по пользователям, запросы к ним идут с `user_id`.

| Таблица | Что хранит |
|---|---|
| `users` | Пользователей |
| `items` | Задачи, напоминания, встречи, правила повтора, источник записи |
| `messages` | Реплики диалога и журнал вызовов |
| `dialog_state` | Последние упомянутые записи |
| `embedding_cache` | Векторы для поиска |

Дата и время хранятся как местные, без часового пояса. Текущее время считается в `APP_TIMEZONE`.

## Структура

```
assistant/
  voice/            SpeechKit (yandex_speech.py), faster-whisper и OpenAI (speech.py)
  nlu/              клиент модели, инструменты, проверка аргументов, диалог
  services/         задачи, повторы, конфликты, расписание, поиск, импорт CSV, .ics
  storage/          SQLite, репозиторий, кэш эмбеддингов
  web/              FastAPI и страница интерфейса (static/index.html)
  yandex_cloud.py   авторизация Yandex Cloud, эмбеддинги, сообщения об ошибках
  providers.py      выбор провайдеров по .env
  cli.py            команды import-csv, embed, check, export-ics, import-ics, stats
data/               CSV с историей и база assistant.db
tests/              тесты pytest
run.py              запуск сервера
```

Внешние сервисы подключены через интерфейсы `LLMClient`, `SpeechToText`, `TextToSpeech` и `Embedder`. Провайдер выбирается в `.env`, в тестах сервисы заменены фейками.

## Ключи Yandex Cloud

1. Зарегистрируйтесь в консоли https://console.yandex.cloud и создайте платежный аккаунт с российской картой. Пробного периода и стартового гранта для новых клиентов нет (https://yandex.cloud/ru/docs/free-trial/concepts/usage-grant), поэтому сразу пополните баланс на небольшую сумму.
2. Выберите каталог: подойдет `default` или новый. Идентификатор вида `b1g...` показан в консоли рядом с названием каталога. Это `YANDEX_FOLDER_ID`.
3. Откройте https://aistudio.yandex.ru, выберите каталог и нажмите "Создать API-ключ" в правом верхнем углу. AI Studio создаст сервисный аккаунт с ролью `ai.editor` и ключ для моделей, распознавания и синтеза. Скопируйте секретный ключ сразу, потом он не показывается. Это `YANDEX_API_KEY`. Документация: https://aistudio.yandex.ru/docs/en/ai-studio/operations/get-api-key.html
4. Если нужны минимальные права, создайте сервисный аккаунт вручную в консоли, назначьте роли `ai.languageModels.user`, `ai.speechkit-stt.user`, `ai.speechkit-tts.user` и создайте для него API-ключ.

Ошибка `Specified folder ID ... does not match with service account folder ID` значит, что в `YANDEX_FOLDER_ID` указан другой идентификатор. Нужен каталог сервисного аккаунта, он начинается с `b1g`.

Ключ лежит только в `.env`. Этот файл исключен из git, но при передаче папки другому человеку его нужно убрать вручную: расходы по ключу идут на ваш счет.

## Модели и стоимость

По умолчанию работает `yandexgpt-5.1` (YandexGPT Pro 5.1), настройка `YANDEX_GPT_MODEL`. Модель `aliceai-llm-flash` стоит в разы меньше и по документации поддерживает вызов функций: проверьте ее на своих фразах. Есть также `aliceai-llm`. Список моделей: https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/generation/models

Цены AI Studio с НДС за 1000 токенов в синхронном режиме (https://aistudio.yandex.ru/ru/docs/ai-studio/pricing):

| Модель | Вход | Выход |
|---|---|---|
| YandexGPT Pro 5.1 | 0,8 ₽ | 0,8 ₽ |
| Alice AI LLM | 0,5 ₽ | 1,2 ₽ |
| Alice AI LLM Flash | 0,1 ₽ | 0,2 ₽ |
| Эмбеддинги | 0,0101 ₽ | нет |

SpeechKit (https://aistudio.yandex.ru/ru/docs/speechkit/pricing): распознавание 0,1626 ₽ за каждые 15 секунд, синтез 1342 ₽ за 1 млн символов. Ответ в 100 символов стоит около 0,13 ₽.

Примерная стоимость команды: два обращения к модели по 2-2,5 тысячи токенов дают 3-4 ₽ на YandexGPT Pro 5.1 и около 0,5 ₽ на Alice AI LLM Flash. Голос добавит 0,16 ₽ за распознавание и около 0,1 ₽ за озвучку. Это оценка, точный расход виден в консоли Yandex Cloud. Первый импорт истории стоит меньше рубля. Просмотр расписания бесплатный.

## Интерфейс

Микрофон работает на `localhost`, `127.0.0.1` или по https. Нажмите на него, скажите фразу и нажмите еще раз.

- Переключатель "Речь": "сервер" (SpeechKit) или "браузер" (распознавание Chrome).
- Переключатель "Озвучка": "сервер" (SpeechKit), "браузер" (бесплатно) или "выкл". Голос задает `YANDEX_TTS_VOICE`: filipp, ermil, zahar, madi_ru, jane, omazh, marina.

## Другие провайдеры

`PROVIDER=local` работает бесплатно: модель qwen2.5 и эмбеддинги bge-m3 в Ollama (https://ollama.com), распознавание faster-whisper или браузер, озвучка в браузере. После скачивания моделей интернет не нужен.

```bash
ollama pull qwen2.5:7b        # 16 ГБ ОЗУ; для 8 ГБ: ollama pull qwen2.5:3b и LLM_MODEL=qwen2.5:3b
ollama pull bge-m3
pip install -r requirements-whisper.txt   # необязательно: распознавание на сервере
```

Модели занимают около 7 ГБ, с qwen2.5:3b около 4 ГБ. Контекст лучше увеличить до 8192: настройка Context length в Ollama или `OLLAMA_CONTEXT_LENGTH=8192 ollama serve`.

`PROVIDER=openai` и `OPENAI_API_KEY=...` подключают gpt-4o-mini, Whisper, OpenAI TTS и эмбеддинги OpenAI.

Распознавание и озвучка настраиваются отдельно от модели: `STT_ENGINE` (yandex, local, openai, browser) и `TTS_ENGINE` (yandex, openai, browser).

## Что сделано по ТЗ

Основное:

| Пункт | Как сделано |
|---|---|
| Задачи и напоминания | Голосом и текстом, с относительными датами: "завтра", "в пятницу", "через час" |
| Встречи | Название, дата, время, длительность, по умолчанию 60 минут |
| Расписание за период | Вопросом "что у меня на неделе" и в панели "Расписание" с выбором дат и типа |
| Поиск старых записей по смыслу | Эмбеддинги Yandex и совпадение слов, в том числе по истории из CSV |
| Уточняющие вопросы | Без даты, времени или названия ассистент переспрашивает и ничего не создает |
| Голос | SpeechKit, запасной вариант в браузере, текстовый ввод |
| Хранение | SQLite, данные сохраняются после перезапуска |

Дополнительно:

| Пункт | Как сделано |
|---|---|
| Редактирование | Название, дата, время, длительность, повтор, голосом или текстом |
| Удаление | Голосом, текстом или кнопкой в списке |
| Отметка выполнения | Голосом или кнопкой, у повторяющейся задачи отмечается конкретный день |
| Повторяющиеся события | Ежедневно, по будням, еженедельно с выбором дней, ежемесячно, ежегодно; до даты или N раз |
| Пересечение встреч | Проверка при создании и переносе, в том числе с повторами; ассистент спрашивает, ставить ли все равно |
| Контекст диалога | Понимает "перенеси ее на завтра" по последним записям и репликам |
| Неоднозначные запросы | Ассистент перечисляет подходящие записи и спрашивает, какую выбрать |
| Семантический поиск | Есть, с кэшем эмбеддингов |
| Внешний календарь | Экспорт и импорт .ics (Google Календарь, Apple Календарь, Outlook); повторный импорт обновляет записи без дублей |
| Несколько пользователей | Выбор и добавление в интерфейсе, данные и диалоги раздельные |

## Тесты

```bash
pip install -r requirements-dev.txt
python -m pytest
```

Тесты не обращаются к Yandex Cloud, Ollama и OpenAI. Для Yandex поднимается локальная имитация сервера: она проверяет адреса, заголовки авторизации, URI моделей и параметры SpeechKit. Остальные тесты покрывают бизнес-логику, диалог, ответы модели, импорт CSV, кэш эмбеддингов, поиск, .ics и HTTP API.

## Ограничения прототипа

- Качество понимания зависит от модели. Если ассистент путается, сформулируйте короче или выберите модель мощнее.
- SpeechKit распознает фразы до 30 секунд.
- С внешними календарями проект обменивается файлами .ics, двусторонней синхронизации нет.
- Напоминания работают только в открытом окне браузера, push-уведомлений нет.
- Распознавание в браузере работает в Chrome и отправляет звук на серверы Google.
- Паролей нет, пользователь выбирается из списка.
- Все записи хранятся в одном часовом поясе.
- Удаление и перенос повторяющегося события меняют всю серию.
